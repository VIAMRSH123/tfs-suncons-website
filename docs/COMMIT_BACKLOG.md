# Daily Commit Backlog

A queue of real work for this repo, highest-value first. A scheduled Claude Code agent runs each
morning at 09:00 (Asia/Calcutta), takes the **top unchecked item**, does it properly, verifies it,
and commits.

Every item below is drawn from something `docs/06-handover.md` measured and recorded as a gap, or
from reading the code. Nothing here is invented to fill the queue.

## The rules the daily agent follows

1. **One item per run.** Finish it or leave it uncommitted — never commit a half-done item.
2. **Verify before committing.** All three must pass:
   `npm run typecheck` · `npm run lint` · `npm run build`
   The build baseline is 27 pages generated, typecheck and lint clean (handover §4). New tests
   must pass too.
3. **No filler commits.** Whitespace churn, reformatting untouched files, comment padding, or a
   substance-free docs edit are all forbidden. If no item can be done honestly, **make no commit**
   and say so. A gap in the heatmap beats a commit that lies about work.
4. **Read the Next.js docs first.** Per `AGENTS.md`, this is Next.js 16 and its APIs may differ
   from training data — consult `node_modules/next/dist/docs/` before writing framework code.
   `AGENTS.md` is regenerated by `next dev`; commit it with your work rather than reverting it.
5. **Never `git add -A` or `git add .`** — stage named paths only, and never commit `.env`.
6. **Don't regress the motion system.** Since the 22 Oct 2026 redesign it runs without an
   animation library — CSS verbs driven by IntersectionObserver, native sticky pins whose heights
   are set in CSS, canvas loops that pause off screen (`docs/10-redesign-handover.md` §3). Every
   effect has a reduced-motion path and a no-JS final state, and every listener and frame loop is
   cleaned up on unmount. Keep those properties, and don't reintroduce GSAP or Lenis to fix a
   motion bug.
7. **Conventional commit messages** (`feat:`, `fix:`, `test:`, `docs:`, `refactor:`, `perf:`,
   `chore:`) with a body explaining *why* when the subject isn't self-evident.
8. **Append to the log** at the bottom, and tick the item off above.

### A. Regression tests — the repo has none

`docs/06-handover.md` §4 records a long list of behaviours verified **by hand, once**. None of it
is protected against regression, and there is no test runner installed at all. This is the highest
value work available: it turns a one-off manual pass into something that holds.

- [x] **A1 — Install Playwright** and wire `test` / `test:e2e` scripts. Config should build and
      serve the production bundle (`next build && next start`), since most of what needs asserting
      is prerendered output and real headers. Keep it to one dependency.
- [x] **A2 — Legacy redirect tests.** `next.config.ts` defines 13 permanent redirects from the old
      WordPress URLs; handover §4 claims all return 308 to the correct target. Assert every one by
      reading the table from the config rather than hardcoding a second copy.
- [ ] **A3 — Internal link crawl.** Handover §4 claims 25 unique internal links, 0 broken. Make it
      a test that crawls from `/` and fails on any non-200.
- [ ] **A4 — No horizontal overflow** at 320 / 375 / 768 / 1024 / 1280 / 1920, asserted as
      `scrollWidth <= clientWidth` on `<html>`. Handover §4 verified these widths manually; the
      project's own web testing rules require the same set.
- [ ] **A5 — Enquiry API contract.** Four cases, all recorded as verified in §4 and all cheap to
      pin down: valid + webhook configured → 200 and the payload delivered; valid + nothing
      configured → 503 `not_configured`; invalid input → 422 with per-field errors; honeypot
      filled → silent 200 with **nothing delivered**. Stub the webhook receiver locally.
- [ ] **A6 — Content survives without JavaScript.** §4 claims all copy is in the server HTML and a

- [ ] **A7 — Reduced motion.** §5 says this was *never observed* because the environment could not

- [ ] **A8 — Automated accessibility scan.** Add `@axe-core/playwright` and assert zero critical

- [ ] **A9 — Landmark and heading structure.** Skip link focuses the main content, one `<h1>` per

### B. Security

- [ ] **B1 — Add a Content-Security-Policy.** `next.config.ts` ships five security headers but no
      CSP, and handover §9 flags it as required before launch. The project's own web security rules
      require a nonce-based policy rather than `'unsafe-inline'`, which means generating a nonce in
      `middleware.ts` (none exists yet) and threading it through. Ship it
      **`Content-Security-Policy-Report-Only` first**, confirm the real page produces no
      violations, then switch to enforcing in a follow-up commit — a wrong CSP breaks the whole
      site silently.
- [ ] **B2 — Fix the rate limiter's unbounded growth.** In `src/app/api/enquiry/route.ts` the
      `hits` Map is keyed by client IP and **never evicted**, so it grows for the life of the
      instance. Evict expired keys on write (or use a bounded structure). Separate from, and
      smaller than, B3.
- [ ] **B3 — Shared rate-limit store.** §9: the limiter is per-instance, so a multi-instance
      deployment does not actually limit. Needs an external store; pick one only once a deployment
      target is known, so **leave this blocked until then** rather than guessing at infrastructure.

### C. Performance — the JS budget is missed

Handover §4 measured **220.6 kB** of JS against the project's 150 kB landing-page budget:
GSAP + ScrollTrigger ≈ 70 kB, React 19 + Next runtime ≈ 91 kB, app code ≈ 60 kB. The 22 Oct 2026
redesign removed GSAP and Lenis and code-split the below-the-fold sections; first-load JS is now
149–151 kB per page, with React, Next and the Turbopack runtime ≈ 129 kB of that
(`docs/10-redesign-handover.md` §5). Don't win the last kilobyte by cutting a feature (rule 6).

- [ ] **C1 — Record per-route JS in CI-less form.** A script that parses `next build` output into a
      committed baseline file, so a regression is visible in a diff rather than discovered later.
      Do this first: the rest of section C is unmeasurable without it.
- [x] **C2 — Defer GSAP and ScrollTrigger per section.** Dynamic-import the motion modules at the
      section level so routes that do not animate (`/contact`, product detail) stop paying for
      them. Measure against C1's baseline and record the real delta in the commit body — if the
      saving turns out to be negligible, say that and revert rather than keeping churn.
      *Superseded 2026-10-22: the redesign removed GSAP entirely rather than deferring it — a
      lazily loaded pin-spacer would have shifted the page when it arrived. Measured:
      192–203 kB → 149–151 kB first-load JS.*
- [x] **C3 — Re-evaluate Lenis.** §4 names dropping it as part of an ~80 kB saving. Assess whether
      native CSS smooth scroll plus the existing ScrollTrigger wiring can hold the pinned,
      scrubbed rice index. **If it cannot, close this item as "won't do" with the reason** — that
      is a legitimate outcome, not a failure.
      *Done 2026-10-22: removed. The pinned, scrubbed rice index now runs on native
      `position: sticky` plus a small scroll-progress helper (`src/lib/scroll.ts`), so it needs
      neither Lenis nor ScrollTrigger.*
- [ ] **C4 — Lighthouse.** §4 states plainly that no score is claimed because there is no Chrome
      binary available there. Playwright ships Chromium, so a local Lighthouse run against
      `next start` is feasible — but the number only means something against the deployed URL on a
      real network. Run it locally, record it, and label it as localhost rather than quoting it as
      the site's score.

### D. Content accuracy

- [ ] **D1 — Resolve the naming inconsistencies** flagged in `docs/01-company-facts.md` and §8.6:
      "Golden India" vs "Golden Indian", "Bharath Gate" vs "Bharat Gate". The redirect table
